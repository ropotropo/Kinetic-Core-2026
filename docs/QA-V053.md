# v0.5.3 — Cameras, thrust detail and phone interaction

Sole game author: Mykyta Borisov. 15 November 2026.

## Model and presentation

The 4.7 s separation shot follows observed departing hardware, uses effect-free
body bounds and eases back to chase. Restore, low-altitude and reduced-motion
guards prevent an invented or unsuitable shot. Pause freezes its clock; manual
inspection cancels it. The 0.48 s external return retains the ground clamp;
mounted camera poses and incompatible physical frames remain exact.

Inspection uses bounded viewport-normalized one-pointer rotation and separate
two-pointer zoom, rebasing on pointer-count changes and clearing on lost input.
The descent plume responds to applied thrust, has soft tapered gas-like edges,
and vanishes at cutoff. This is a visual effect, not a fluid simulation. Detached
custom hardware hides copied engine/RCS effects without hiding source hardware.
The atmospheric trail starts beyond the active flame tips, centered across the
active engines; its wider, softer puffs retain the existing finite history pool.

Docking port detail retains the original physical contact plane and envelope.
Only Docking camera receives subtle sensor grain; the reticle and instruments
stay sharp. Actual capture changes to a joined external view before the debrief;
Inspect docked craft dismisses that debrief and orbits the joined hardware.

Camera selection/explicit close restores the prior running state. Pre-paused
flight, Escape, background/visibility/context loss and stage depletion retain
their pause guards. Other tools continue to require explicit Resume.

The pressure indicator uses actual corotating airspeed pressure: amber at 88 kPa,
red at 104.5 kPa, with the unchanged strict failure boundary above 110 kPa. These
are 80%/95% of a fictional structural ceiling, not certified vehicle limits. The
point-mass model has no angle-of-attack bending, lift, heating or wind model; a
wrong pitch does not itself trigger failure. Proper acceleration is not given an
invented structural g limit.

Workshop selection shows dimensions above the attachment list. Empty points open
compatible Hardware; Add/Replace is an explicit confirmation. The legacy world
selector uses the same globe rail as mission planning, with an always-reachable
Inspect action. Phone Vehicle/Destination tabs sit at the scene bottom center;
duplicate bottom practice links are removed. The KC brand opens mission home.
New per-world landing counters require an observed successful touchdown, reject
unknown/unconfirmed events and never infer totals from older boolean badges.
Counters are local to the current browser and origin.

## Limits

These are browser viewport checks, not physical-iPhone multitouch/GPU acceptance.
Pinch transitions and cut/zero-thrust response have automated regression coverage;
a new full manual capture and full Earth-to-Moon run were not repeated for these
presentation-only changes. Capture criteria remain covered by the numerical suite.
The detailed lunar terrain/crew/science stage is still tracked separately in
LUNAR-EXPERIENCE-NEXT.md. Native installers remain the separately labelled 0.5.0.
